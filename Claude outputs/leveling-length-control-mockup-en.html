Purpose and how the data is joined

The goal of this page is to answer one question for the operator and the manager: "At this point in the coil, how should the line be controlled?" — tension output, line speed, and when to step them down as the coil gets smaller. To do that, three sources are combined:
  • ERP work order (erp_data, MariaDB) — joined by coil ID. Gives customer, spec (thickness × width), weight, status. Weight + spec are converted into the coil's total length, which becomes the x-axis.
  • PLC log (LEVELING_DATA, MariaDB, one row every ~2 s) — joined by coil ID. Gives cut length setting, per-stroke movement, inverter load, cycle time. Stroke resets are counted to compute the cumulative length processed so far.
  • Tension controller readings (ai_tension_readings, Supabase, camera + AI every 2–5 min) — joined by time: a reading is attributed to the coil that was running at captured_at, and placed on the length axis at the cumulative length reached at that moment.
Everything below uses today's real values (2026-09-03, KST). The purple boxes are annotations for review, not part of the final page. The "same-spec history" recommendations are illustrative — see the honesty note in the guide section.

How position is computed — and a correction to the existing screens. The PLC has no cumulative-length column. MOVELENSV climbs from 0 toward the cut length on every stroke and drops back to 0 when the sheet is cut; each drop is counted as one sheet, × CUTLENSET = length processed. The stroke count shown by the current tools (966) simply counts 2-second rows where CYCLETM > 0; since CYCLETM is a counter that rises 0→9.4 s within one stroke, each sheet is counted 3–4 times. Today's log shows a real sheet takes ≈ 19.5 s (9.4 s stroke + ≈ 10 s feed/stop), i.e. ≈ 203 sheets / 608 m by 09:40 — consistent with the derived 1,432 m total. This page uses the reset-based count. Remaining diameter is estimated from remaining length, thickness and the 508 mm core.

Join rule in detail. ERP and PLC rows share COIL_ID. Each tension reading's captured_at is matched to the coil with RUN=1 at that time, and to the number of sheets cut up to that moment × cut length = its position on the x-axis. Readings arrive every 2–5 minutes, so on the length axis they are 40–120 m apart; between readings the line is drawn as a step (last setting holds). The history band is built from completed coils with the same thickness (±0.03 mm) and width, each normalised to 0–100 % of its own length before averaging, so coils of different weights can be compared.

Where the recommendations come from — and their current limit. Phase 1 shows, per length segment, the median tension and speed actually used on previous coils of the same spec (same approach as the slitting AI Helper's recommend_for mode). If this coil's cycle time or inverter load is worse than history, the guide suggests one step more conservative. Honest caveat: tension readings only exist since 2 Sep and only 11 leveling coils have ever been tagged with a coil ID, so there is not yet enough history to produce per-spec recommendations. Until coils accumulate, the guide shows this coil's own measured profile plus "setting changed here → cycle time afterwards", and the history band/recommendations fill in automatically as data grows. The values in this mockup's guide are examples of the final form, not measured recommendations.

Optional steps that make the mapping exact:
① Have ocr_monitor_production.py store the running COIL_ID and the sheet count at capture time — removes the need for time matching.
② If the controller's tension_rate (currently always read as 0.0) or remaining diameter becomes readable, length can be cross-checked without the PLC.
③ Collecting a cut-counter tag from the PLC turns the reset-based estimate into a measured value.

Implementation plan (after approval)

  • File: public/leveling-length-guide.html (vanilla JS, inline styles, Pretendard via jsDelivr, same conventions as the other public/*.html tools) + a card in LabPage.jsx under 레벨링 공정 관리 with external: true. Office-PC layout; an EN mirror can follow the KR/EN pattern used by the slitting tools.
  • Backend: one new mode in leveler-explore, e.g. leveling_length_profile=<coil>&leveling_work_date=<date>, that returns the reset-based sheet count over time (timestamp of each MOVELENSV drop) plus per-sheet cycle and load. A second mode, leveling_history=<thickness>&width=…, returns length-normalised profiles of completed same-spec coils. Everything else reuses existing modes and the Supabase anon read of ai_tension_readings.
  • Client logic: total length from ERP weight/spec; time→length mapping for tension readings; segment boundaries at 0 / 250 / 750 / 1,200 m by default (configurable, or as % of total length); recommendation = per-segment median of history, with a conservative step if current cycle/load is worse.
  • Refresh: 20 s. KST "today" via the double-offset-safe pattern; MariaDB timestamps treated as KST wall-clock.
  • Out of scope for phase 1: changing the OCR script (phase 2, improves accuracy), mobile layout, login.
