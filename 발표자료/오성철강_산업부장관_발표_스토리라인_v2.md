# 3막 · 목표를 다시 세웠습니다

## 6장 — 밖에서 배운 방식을 꺼냈습니다

통신망은 장비만 감시하지 않습니다. 신청을 받아 개통하고, 끝나면 통보하고,
고객이 마이페이지에서 24시간 확인하고, 사용 이력을 보고 먼저 제안합니다.
그 전체를 옮겼습니다.

| KT에서 하던 일 | 오성철강에서 하는 일 |
|---|---|
| 모든 장비를 연결한다 | 설비 PLC 연결 — 2초 간격, 182만 건 |
| 실시간으로 감시한다 | 라인 관제·현장 대시보드·HMI 미러 |
| 누구나 하도록 SOP를 만든다 | 태블릿 키오스크·AI 헬퍼 (한국어·영어) |
| 장애를 분석해 재발을 막는다 | 코일 상세분석·원인분석·이상 알람 |
| **신청을 받아 자동으로 개통한다** | **카톡·포털 주문 → 작업지시 자동 생성·하달** |
| **완료되면 고객에게 통보한다** | **작업 완료·출고 자동 통보, 미출고 자동 팩스** |
| **마이페이지에서 24시간 조회한다** | **고객 포털 — 재고·작업·출고·단가 실시간** |
| **사용 이력을 보고 먼저 제안한다** | **조용해진 거래처 자동 탐지 → 영업이 먼저 연락** |

위 네 줄은 공장 안, 아래 네 줄은 고객 쪽입니다.
**두 번째 실패는 정확히 아래 네 줄이 없어서 생긴 일이었습니다.**

## 7장 — 사업 목표를 셋으로 다시 세웠습니다

### 최상위 목표

> **"잘 만드는 회사"가 아니라 "값을 받는 회사"가 된다.**
> 우리가 만든 품질을 고객이 직접 확인하게 한다.

### 목표 1 · 누구나, 빠르게, 불량 없이 만든다
작업 전에 비슷한 작업을 어떻게 했는지 보고 / 작업 중에 지금이 빠른지 늦은지 알고 /
끝나면 언제든 되돌아보고 / 불량이 나면 원인을 끝까지 찾는다.
→ **첫 번째 실패를 교정한 목표.** 장비를 바꾸는 게 아니라 쓰는 방법을 바꾼다.

### 목표 2 · 주문에서 완료 통보까지 사람 손 없이 흐른다
접수 → 확인 → 작업지시 생성 → 하달 → 생산 → 완료 → 출고 → 통보.
→ **1번과 3번을 잇는 다리.** 이게 없으면 잘 만들어도 고객에게 닿지 않는다.

### 목표 3 · 고객이 24시간 확인하고, 우리가 먼저 찾아간다
조회(재고·작업·출고·단가) + 증명(품질 리포트) + 선제 영업(휴면 거래처 탐지).
→ **두 번째 실패를 교정한 목표.** 좋은 서비스를 만드는 게 아니라 고객이 쓰게 만든다.

# 4막 · 목표 1을 이렇게 풀었습니다

## 8장 — 작업 전 : 전에 비슷한 작업은 어떻게 했나

**문제.** 같은 사양을 예전에 어떻게 돌렸는지 아무도 모릅니다. 사람마다 다르게 돌립니다.
숙련공은 알지만 그 지식은 문서가 아니라 머릿속에 있습니다.

**AI가 한 일.**
작업지시서의 규격에서 두께를 읽어내고, 두께 ±0.03mm 이내이면서 상태가 '완료'인
과거 코일을 최대 30건까지 찾습니다. 그 코일들의 PLC 실측 기록 중 **실제 가동 중이던
구간(RUN=1)만** 골라, 길이 구간별 평균 속도와 4구역 텐션 프로파일을 계산합니다.
정지·로딩 구간이 섞이면 평균이 왜곡되기 때문에 이 필터가 핵심입니다.
여기에 같은 사양 코일들의 실제 소요시간 평균을 더해 예상 작업시간까지 제시합니다.

> **사람의 기억이 아니라, 과거 실측 데이터가 기준이 되었습니다.**

**세퍼레이터 셋팅.** 40년 공장장이 머릿속으로 계산하던 스페이서 조합을
태블릿이 큰 글씨로 알려줍니다. 이 서비스는 **현장 직원의 요청으로 시작됐습니다.**
슬리팅2가 진행중으로 바뀌면 키오스크가 알아서 셋팅 화면으로 전환됩니다.

**관련 서비스.** AI 헬퍼(지난작업보기) / 세퍼레이터 셋팅 계산기 / 세퍼레이터 태블릿 키오스크 /
원자재 코일 검색(발주서 매칭) / 슬리터1·2 배정 변경 / 레벨링 작업 가이드(외국인 근로자용)

## 9장 — 작업 중 : 지금 빠른가 늦은가

**문제.** 작업 중에는 비교할 대상이 없습니다. 잘 돌고 있는지 아무도 모릅니다.

**AI가 한 일.**
진행 중인 코일의 최신 PLC 기록 한 줄을 읽어, 같은 사양 권장 프로파일의
**같은 길이 지점**과 비교합니다. 그 결과를 적정·느림·빠름으로 표시합니다.
현장은 폰으로 봅니다. 한국어판과 영어판을 따로 만들었습니다.

**통신 포트가 없는 장비.**
텐션 컨트롤러(PR-DTC-3100)는 데이터 출력 단자가 아예 없는 옛날 장비입니다.
값을 꺼내려면 장비를 바꿔야 하고, 그건 수천만 원입니다.
그래서 **폰 IP카메라를 LCD 앞에 두고 1분마다 촬영해, AI 비전 모델이 숫자를 읽게 했습니다.**
출력%·전압·두께·시작경·장력설정·장력율 6개 값이 자동으로 저장됩니다.
카메라를 설치하기 전에, 이미 찍어둔 사진 폴더로 인식 정확도를 먼저 검증했습니다.
해상도를 640px부터 128px까지 낮춰가며 어디까지 읽히는지도 실험했습니다.

> **장비를 바꾸지 않고 데이터를 얻었습니다.
> 억대 설비 교체 대신, 폰 한 대였습니다.**

**관련 서비스.** AI 헬퍼(작업용) / AI 헬퍼 모바일 한·영 / 작업현황 대시보드 1·2·3 /
레벨링 라인 통합 관제(20초 갱신) / 레벨링 실시간 전체 데이터(5초 갱신) /
PR-DTC-3100 실시간 인식 / AI 인식 검증(개발용)

## 10장 — 작업 후 : 언제든 되돌아본다

**문제.** 불량이 나와도 "그때 어떻게 돌렸지"를 아무도 답하지 못합니다.

**AI가 한 일.**
코일번호와 길이를 넣으면 그 지점의 속도·텐션 4구역·사이클타임·RUN 신호가
그대로 나옵니다. 길이 슬라이더를 움직이면 전 구간을 훑을 수 있습니다.
레벨링은 박스별로 행정 하나하나까지 들어갑니다.
기사님이 전화하면 거래처명만 넣어 레벨링·슬리터1·슬리터2 전체에서 찾습니다.
이미 출고된 코일은 자동으로 걸러집니다.

**관련 서비스.** 슬리터2 운행 정보 모니터 한·영 / 코일 작업 상세 분석 /
레벨링 코일 상세분석 / 레벨링 PLC 상세 조회 / 레벨링 통합 타임라인 /
레벨링 공정 현황 모니터링(3단계 드릴다운) / 작업 확인(거래처별 검색)

## 11장 — 불량 : 원인을 끝까지 판다

**문제.** 불량의 원인을 짐작만 하고 넘어갑니다. 그래서 같은 불량이 반복됩니다.

**AI가 한 일 — 실제 사례 세 가지.**

**하나. 텐션 센서 고장을 데이터가 찾아냈습니다.**
코일 60건, 2주치 기록을 한 번에 훑었습니다. 사람이 하면 며칠 걸릴 일입니다.
실제 가동 중(RUN=1, 라인속도 50 이상) 구간만 봤더니,
55건은 4구역 텐션이 속도에 비례해 정상적으로 움직였는데
**5건은 2·3·4구역 텐션이 가동 내내 정확히 0이었습니다.**
1구역도 1~2 근처였습니다. 그런데 라인은 140~153m/분으로 정상 주행 중이었습니다.
가공 문제가 아니라 **센서 배선 문제**였습니다.
이 판정 규칙을 화면에 알람으로 넣었습니다 — 구간 평균 속도가 20 이상인데
특정 구역 평균 텐션이 5 미만이면 경고가 뜹니다.

**둘. 남의 시스템 데이터까지 검증했습니다.**
외부 표면검사 시스템의 API를 직접 조사했습니다. 작업 1,953건, 결함 88,059건.
코일 20건을 표본으로 뜯어봤더니 **30%가 영향을 받았고,
일부 코일은 결함의 최대 94.2%가 실제가 아닌 데모 데이터였습니다.**
전체 이벤트의 33%에 해당합니다.
두께 측정은 코일 5건을 표본 조사했더니 **전부 0건** — 아예 돌지 않고 있었습니다.
카메라 구성도 맞지 않았습니다. API 응답은 3대인데 실제 이벤트에는 8종 카메라명이 있었습니다.

**셋. 우리 시스템도 의심했습니다.**
우리가 만든 화면들에서 시각이 9시간씩 밀려 찍히던 버그를 찾아 전 화면을 고쳤습니다.
길이 값이 소수점에서 잘려 저장되던 문제도 긴급 수정하고 데이터를 복구했습니다.

> **우리는 숫자를 믿지 않고 확인합니다.**

**관련 서비스.** 장애 원인 분석(AI, PLC 이력+CCTV) / 표면검사 AI(결함 위치·전후 영상) /
텐션 이상 알람 / 레벨링 공정 리듬(이상 구간 탐지)

# 5막 · 목표 2를 이렇게 풀었습니다

## 12장 — 주문에서 통보까지, 사람 손을 거치지 않습니다

**문제.** 그린ERP에 작업지시서가 올라오면, 사람이 그걸 보고 현장 슬리팅 대시보드에
**손으로 다시 입력**했습니다. 빠뜨리면 현장이 모릅니다. 중복 입력하면 꼬입니다.

**AI가 한 일.**
자동 동기화 함수를 만들고, 같은 지시서가 두 번 들어가지 않도록 중복 방지 테이블을 붙였습니다.
처음에는 **실제로 쓰지 않고 모의 실행(dry-run)으로만 돌려** 타이밍과 정확성을 검증한 뒤
실가동으로 전환했습니다. 지금은 업무시간 동안 **1분마다 자동으로 등록됩니다.**

7단계 흐름: 카톡·포털 주문 → 시스템 자동 확인 → 작업지시서 생성 → 현장 하달 →
생산 → 완료 → 출고 요청·통보.
팩스로 들어오는 작업요청서는 AI가 읽어 초안을 만듭니다.

**관련 서비스.** 대시보드 자동연동(RPA 대체) / 대시보드 자동연동 모니터링 /

# 6막 · 목표 3을 이렇게 풀었습니다

**챗봇.** 고객이 전화로 묻던 것을 이제 채팅으로 묻습니다.

범위 밖 질문에는 답하지 않도록 제한했습니다. 진행 건수, 미출고, 미수금,
